# GUIDE 取消／退款規則由方案設定

> Owner Decision：2026-08-31
> 關聯：#41、#12、#42、#46

## 1. 誰決定取消／退款規則

GUIDE 的旅客主動取消與退款規則採「**每個導遊／每個方案可自行設定，Midao 提供預設範本**」模式。

- 不使用全平台單一、不可修改的取消政策。
- 不要求每次取消都由導遊臨時人工判斷。
- Midao 提供一組預設範本，讓不熟悉後台的導遊可直接套用。
- 導遊可在每個 Trip Plan 的進階設定調整該方案的取消／退款規則。
- 方案成立／訂單成交時，必須把當下實際適用的取消政策保存為 order snapshot（訂單當下固定版本）；Plan 日後修改不可回頭改既有訂單的權益與退款規則。
- 旅客在下單前與訂單頁都必須能看到白話版取消政策，不能只藏在後台。
- 導遊若使用 Midao 預設範本，UI 應明確標示「使用 Midao 建議規則」，並允許一鍵改成自訂。

## 2. Midao 預設範本採三段式

Owner 選擇：**A，三段式**。

Midao 預設取消政策的時間區間固定先採：

1. **出發前 8 天以上**
2. **出發前 4～7 天**
3. **出發前 0～3 天**

這三段是 Midao 預設範本的時間骨架，不代表所有導遊都必須使用；導遊仍可在各 Trip Plan 自行設定其他規則。

目前只拍板「分三段與時間區間」，**尚未拍板每一段實際退多少、訂金是否可退、退款手續費由誰負擔**。施工者不得自行填入退款百分比。

## 3. UI 原則

方案進階設定應提供：

- `使用 Midao 建議取消規則`（預設三段式範本）
- `自行設定`

預設範本可用白話顯示：

```text
出發前 8 天以上
出發前 4～7 天
出發前 0～3 天
```

避免要求導遊理解 refund policy enum、penalty rule 等技術名稱。

取消規則屬低頻商業設定，放在進階層，不塞進 Quick Edit（快速編輯）首頁。

## 4. 實作邊界

- #42：方案進階設定 UI 與 snapshot 一致性。
- #41：取消後對成團狀態、有效人數、退款待辦的生命週期影響。
- #12：實際退款金流／退款狀態，不能自行發明不同政策。
- #46：旅客下單前與訂單頁誠實顯示適用政策。

## 5. 尚未裁示

以下數值／行為必須後續逐題裁示，不得自行推論：

1. 三個時間區間各自退款比例。
2. 訂金在旅客主動取消時是否可退、何時不退。
3. 金流退款手續費由誰負擔。
4. 已成團後旅客取消造成低於成團門檻時，除既有 AT_RISK 流程外是否有額外補償規則。

在上述細節未裁示前，施工者可建立可配置資料模型與 UI 架構，但不得自行寫死退款比例或沒收訂金規則。
