# GUIDE 取消／退款規則由方案設定

> Owner Decision：2026-08-31；2026-09-02 依 GUIDE SaaS 平台角色重新分類「建議預設」與「平台底線」
> 關聯：#41、#12、#42、#46、#48
> 最新上位決策：`docs/decisions/2026-09-02-guide-saas-platform-role-and-dispute-defaults.md`

## 0. 2026-09-02 上位原則

Midao／GUIDE 後台的主要角色是 SaaS（訂閱式後台）＋前台曝光／上架，不是導遊與旅客的退款仲裁中心。

因此本文件中的三段式、不可退成本、訂金、退款手續費、附件分享與退款明細呈現，除資料安全／真實性底線外，都應理解為 **Midao 建議預設，可由導遊在 Trip Plan 自訂**，不是全平台不可修改的商業規則。

較新的 Owner Decision 覆蓋本文件早期「必須」措辭中屬於商業政策的部分。施工時不得把建議範本硬寫成不可修改的全平台規則。

平台仍固定要求：

- 已成交訂單保存當時適用的價格與政策 snapshot（固定版本），不得事後偷偷改成更不利條件。
- 金流與退款狀態必須誠實，`REFUND_PENDING` 不能冒充 `REFUNDED`。
- 退款不得形成負數、重複退款／重複扣款或超過實際已付款金額。
- tenant（使用後台的一個導遊／工作室帳戶）與 order 的資料／附件權限必須隔離。
- 系統不得自行捏造 provider（金流商）沒有回傳或無證據支持的費用。
- 自訂政策仍須遵守適用法律、強制規範與金流商規則。

## 1. 誰決定取消／退款規則

GUIDE 的旅客主動取消與退款規則採「**每個導遊／每個方案可自行設定，Midao 提供預設範本**」模式。

- 不使用全平台單一、不可修改的取消政策。
- 不要求每次取消都由導遊臨時人工判斷。
- Midao 提供一組預設範本，讓不熟悉後台的導遊可直接套用。
- 導遊可在每個 Trip Plan 的進階設定調整該方案的取消／退款規則。
- 訂單成交時，把當下實際適用的取消政策保存為 order snapshot（訂單當下固定版本）；Plan 日後修改不可回頭污染既有訂單。
- 旅客下單前與訂單頁應看到該方案實際適用的白話政策。
- 導遊若使用 Midao 預設範本，UI 明確標示「使用 Midao 建議規則」，並允許一鍵改成自訂或恢復建議值。

## 2. Midao 建議範本採三段式

Owner 選擇：**A，三段式。**

Midao 建議取消政策時間區間：

1. **出發前 8 天以上**
2. **出發前 4～7 天**
3. **出發前 0～3 天**

這三段只是 default template（建議預設範本）的時間骨架。導遊可依方案改成其他區間、no-show（未出席）規則、特殊票券或客製包團條件。

## 3. Midao 建議退款基準：扣除實際不可退成本後退款

Owner 選擇：**B，以實際不可退成本為建議基準，且導遊可客製。**

Midao 建議範本不採固定「100%／70%／50%」退款比例，而採：

`已付款總額（含訂金）－已實際發生且確實不可退的必要成本－金流商實際且確實不退的退款手續費＝建議退款金額`

建議原則：

- 尚未發生、可以取消退回或只是估算的成本，不建議列為不可退成本。
- 同一成本不重複計算。
- 建議退款最低為 0，不形成旅客反向欠款。
- 導遊可在每個 Trip Plan 自訂其他取消／退款方式；Midao 預設不是平台硬性統一政策。
- 成交後使用訂單 snapshot，不因 Plan 日後改規則回頭重算舊單。

三段式仍可用於 UI 說明、提醒與導遊自訂差異，但 Midao 不因三段時間寫死固定退款百分比。

## 4. 不可退成本明細與證據附件

Owner 選擇：**B，Midao 建議成本以項目＋金額記錄，證據附件選填。**

使用 Midao 建議退款流程時：

- 每筆不可退成本建議分開填寫 **項目名稱＋金額**，方便導遊自己對帳與向旅客說明。
- 可選擇上傳收據、訂單截圖、付款截圖或其他佐證，附件不是退款流程的必要條件。
- 有附件不代表 Midao 自動判定該成本合理或可向旅客扣除。
- 導遊若採自訂政策，可使用不同的退款計算方式；後台仍應保留實際退款金額與必要 audit（操作紀錄）。
- 成本明細與附件的 tenant／order 權限隔離屬平台底線，不可關閉。

白話 UI 建議：

```text
不可退成本

項目名稱：包車訂金
金額：NT$ 2,000
附件：＋ 上傳附件（選填）

＋ 新增一筆成本
```

## 5. 旅客退款結果：建議提供逐筆扣款明細

Owner 原選擇：**A，旅客可看到每一筆不可退成本的項目名稱與金額。**

在 2026-09-02 SaaS 角色上位原則下，這項改列為 **Midao 建議預設**：

```text
已付款                 NT$ 5,000

不可退成本
包車不可退訂金         NT$ 1,500
門票不可退費用         NT$   500
-------------------------------
不可退成本合計         NT$ 2,000
退款金額               NT$ 3,000
```

Midao 預設使用透明明細，因為較能降低來回詢問與爭議；導遊若採自訂政策，可選擇不同顯示方式，但仍須符合適用法規與實際交易紀錄，且系統不可偽造金額或狀態。

## 6. 證據附件預設不公開，導遊可選擇分享

Owner 選擇：**B，附件預設不公開給旅客，但導遊可針對單筆附件選擇分享。**

此為 Midao 建議 UX：

- 收據、訂單截圖、付款截圖預設只供 tenant 後台授權人員查看。
- 每筆附件可提供 `分享給旅客查看` 開關，預設關閉。
- 導遊主動分享後，只有該 TourOrder 的授權旅客可查看，不得產生永久公開 URL。
- 關閉分享後停止後續旅客存取；歷史操作保留 audit。
- 分享前提醒導遊檢查姓名、電話、帳號、交易資訊等內容。

附件的權限隔離與不可永久公開屬平台安全底線；「要不要分享」由導遊決定。

```text
附件：包車訂金收據.jpg
[ ] 分享給旅客查看
```

## 7. 訂金預設納入已付款總額，不因名稱自動沒收

Owner 選擇：**A，Midao 建議把訂金視為已付款的一部分。**

建議範本：

- `DEPOSIT_FIXED`（固定訂金）與 `DEPOSIT_PERCENT`（比例訂金）的實收款都納入已付款總額。
- Midao 建議不因名稱叫「訂金」就自動全額沒收。
- 若只付訂金 NT$2,000、實際不可退成本 NT$500，建議退款 NT$1,500。
- 導遊可在個別 Trip Plan 自訂「訂金不退」或其他處理方式，但必須在旅客下單前揭露並保存成交 snapshot；不得事後才改成更不利條件。

Midao 的預設 UI 不預勾「訂金一律不退」，但自訂政策可以提供合法、清楚揭露的可配置選項。

## 8. 金流退款手續費

Owner 選擇：**B，Midao 建議由旅客負擔金流商實際產生且確實不退的退款手續費。**

建議範本：

- 只有 payment provider（金流商）對該筆退款實際收取、且確實不會退回商家時，才帶入退款試算。
- provider 沒有收費、原交易手續費會退回或系統沒有可靠資料時，不自動猜測固定百分比／固定金額。
- 在 Midao 建議透明模式中，金流費可作為一筆明細顯示。
- 導遊可自訂由自己吸收金流費，或依已揭露政策處理。
- 系統不得捏造不存在的 provider 費用；這是資料真實性底線。

例如：

```text
已付款                         NT$ 5,000
包車不可退訂金                 NT$ 1,500
金流商實際不退退款手續費       NT$   30
---------------------------------------
建議退款                       NT$ 3,470
```

## 9. 導遊／業者主動取消與其他爭議情境

最新上位決策統一見：`docs/decisions/2026-09-02-guide-saas-platform-role-and-dispute-defaults.md`。

Midao 建議：

- 導遊／業者主動取消整團：全額退款，金流實際且不退費用由業者吸收。
- 未達最低成團而取消：建議全額退款。
- 天候、災害、交通中斷：優先免費改期；無法改期再建議全額退款。
- no-show 與特殊客製情境：依每個方案自訂政策處理。
- 一般爭議由導遊與旅客協商，Midao 提供紀錄與工具，不建立逐案仲裁引擎。

以上皆為建議預設，除平台安全／真實性底線與適用強制規範外，導遊可調整。

## 10. UI 原則

方案進階設定提供：

- `使用 Midao 建議取消規則`
- `自行設定`
- `恢復 Midao 建議`

建議範本可白話顯示：

```text
取消退款方式
● 使用 Midao 建議規則
  已付款（包含訂金）扣除已實際支付且無法退回的必要成本與實際金流退款手續費後，其餘退款
○ 自行設定
```

自訂層可提供時間區間、訂金處理、no-show、特殊票券、改期與退款方式，但不要要求導遊理解 refund policy enum、penalty rule 等技術名稱。

取消規則屬低頻商業設定，放在 Advanced Settings（進階設定），不塞進 Quick Edit（快速編輯）首頁。

## 11. 實作邊界

- #42：提供 Midao 建議／自行設定／恢復建議的 UI，並維持 policy snapshot 一致性。
- #41：取消後對成團狀態、有效人數與退款待辦的生命週期影響；不自行硬寫全平台退款政策。
- #12：實際退款金流／退款狀態與 provider 真實資料；不能把申請退款冒充完成退款。
- #46：旅客看到成交時實際適用的政策與真實退款狀態，不把 Midao 建議冒充導遊實際政策。
- #48：SaaS／曝光收費與退款爭議責任分離。

## 12. 已收斂，不再列為一般 Owner 阻塞

以下退款細節不再逐題請 Owner 裁示；依 2026-09-02 上位方向採合理 Midao 建議預設，並保留導遊自訂：

- 未達最低成團取消。
- 天候／不可抗力改期與退款。
- no-show／特殊票券／客製包團。
- 善意退款與例外協商。
- 已成團後個別旅客取消造成 `AT_RISK` 時的價格影響，依 `docs/decisions/2026-09-02-guide-formed-price-protection.md`，繼續出團不補差額。

只有涉及新平台責任模型、代收代付／履約保證、法律強制衝突、Production 授權或新的商業模式時才重新升級 Owner 決策。
