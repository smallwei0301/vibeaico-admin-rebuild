# GUIDE 取消／退款規則由方案設定

> Owner Decision：2026-08-31；2026-09-02 補充旅客退款明細、附件分享與訂金退款基準
> 關聯：#41、#12、#42、#46

## 1. 誰決定取消／退款規則

GUIDE 的旅客主動取消與退款規則採「**每個導遊／每個方案可自行設定，Midao 提供預設範本**」模式。

- 不使用全平台單一、不可修改的取消政策。
- 不要求每次取消都由導遊臨時人工判斷。
- Midao 提供一組預設範本，讓不熟悉後台的導遊可直接套用。
- 導遊可在每個 Trip Plan 的進階設定調整該方案的取消／退款規則。
- 方案成立／訂單成交時，必須把當下實際適用的取消政策保存為 order snapshot（訂單當下固定版本）；Plan 日後修改不可回頭改既有訂單的權益與退款規則。
- 旅客在下單前與訂單頁都必須能看到白話版取消政策，不能只藏在後台。
- 導遊若使用 Midao 預設範本，UI 應明確標示「使用 Midao 建議規則」，並允許一鍵改成自訂。

## 2. Midao 預設範本採三段式

Owner 選擇：**A，三段式**。

Midao 預設取消政策的時間區間固定先採：

1. **出發前 8 天以上**
2. **出發前 4～7 天**
3. **出發前 0～3 天**

這三段是 Midao 預設範本的時間骨架，不代表所有導遊都必須使用；導遊仍可在各 Trip Plan 自行設定其他規則。

## 3. Midao 預設退款基準：扣除實際不可退成本後退款

Owner 選擇：**B，以實際不可退成本為基準，且導遊可客製。**

Midao 預設範本不採固定「100%／70%／50%」退款比例，而採以下原則：

- 旅客主動取消時，先計算該筆訂單已實際發生、且確實無法退回／取消的必要成本。
- 從旅客已付款金額中扣除上述實際不可退成本後，其餘金額作為退款基礎。
- 不可把尚未發生、可取消、可退回或只是預估的成本直接當成不可退成本。
- 同一成本不得重複扣除。
- 若可退款餘額小於 0，退款金額最低為 0，不得形成旅客反向欠款。
- 導遊仍可在每個 Trip Plan 自訂其他取消／退款方式；Midao 預設只是快速範本，不是平台硬性統一政策。
- 成交時必須把實際採用的退款規則 snapshot 到訂單，之後 Plan 改規則不追溯舊訂單。

三段式時間區間仍保留，用於 UI 說明、提醒與未來可設定差異，但 **Midao 預設不因三段時間直接寫死固定退款百分比**。

## 4. 不可退成本明細與證據附件

Owner 選擇：**B，成本明細必填，證據為可選附件。**

導遊在退款流程中主張「實際不可退成本」時：

- 每一筆成本都必須填寫 **項目名稱＋金額**，不能只輸入一個沒有明細的總扣款數字。
- 可選擇上傳收據、訂單截圖、付款截圖或其他佐證作為附件，但 **附件不是完成退款流程的強制條件**。
- 沒有附件時，系統不得因此自動阻擋退款計算或要求導遊一定補證明才能繼續。
- 有附件時，附件只是該筆成本的補充紀錄，不代表系統自動判定該成本一定合理或一定不可退。
- 成本明細與附件都必須保留 tenant（使用後台的一個導遊／工作室帳戶）隔離與操作紀錄；不可把其他租戶附件串錯或公開。

白話 UI 建議：

```text
不可退成本

項目名稱：包車訂金
金額：NT$ 2,000
附件：＋ 上傳附件（選填）

＋ 新增一筆成本
```

## 5. 旅客退款結果必須顯示逐筆扣款明細

Owner 選擇：**A，旅客可看到每一筆不可退成本的項目名稱與金額。**

退款結果／旅客訂單頁至少要清楚列出：

- 原已付款金額。
- 每一筆不可退成本的 **項目名稱＋金額**。
- 不可退成本合計。
- 最終退款金額。

例如：

```text
已付款                 NT$ 5,000

不可退成本
包車不可退訂金         NT$ 1,500
門票不可退費用         NT$   500
-------------------------------
不可退成本合計         NT$ 2,000
退款金額               NT$ 3,000
```

不得只對旅客顯示「扣除費用 NT$2,000」而隱藏逐筆項目，避免旅客需要另外詢問退款金額如何算出。

## 6. 證據附件預設不公開，導遊可選擇分享

Owner 選擇：**B，附件預設不公開給旅客，但導遊可針對單筆附件選擇分享。**

- 旅客一定看得到第 5 節規定的「項目名稱＋金額」明細；**是否分享附件不影響明細透明義務**。
- 收據、訂單截圖、付款截圖等證據附件預設只供該 tenant 後台授權人員查看。
- 每一筆附件可提供明確的 `分享給旅客查看` 開關；預設為關閉。
- 導遊主動開啟分享後，只有該筆 TourOrder 的旅客／受授權檢視者可查看，不得產生永久公開 URL。
- 若導遊之後關閉分享，系統應停止後續旅客存取；歷史操作需留下 audit（操作紀錄）。
- UI 在分享前應提醒導遊確認附件內是否含不希望公開的姓名、電話、帳號、交易資訊等內容。
- 不得因附件未分享，而把該筆成本項目與金額一起隱藏。

白話 UI 可呈現：

```text
附件：包車訂金收據.jpg
[ ] 分享給旅客查看
```

## 7. 訂金預設納入已付款總額，不因名稱自動沒收

Owner 選擇：**A，訂金也是已付款的一部分。**

Midao 建議取消／退款規則下：

- `DEPOSIT_FIXED`（固定訂金）與 `DEPOSIT_PERCENT`（比例訂金）實際已收的訂金，都納入「旅客已付款總額」。
- **不得因款項名稱是「訂金」就自動判定不退或直接全額沒收。**
- 預設計算仍採：`已付款總額 − 實際不可退成本 = 應退款金額`。
- 若旅客目前只付訂金，仍用相同公式計算。例如已付訂金 NT$2,000、實際不可退成本 NT$500，則退款基礎為 NT$1,500。
- 若實際不可退成本高於已付款總額，退款最低為 0，不形成旅客反向欠款。
- 導遊仍可在個別 Trip Plan 選擇自訂取消政策；若自訂政策對訂金有不同處理，必須在旅客下單前白話揭露，並在成交時保存 order snapshot（訂單當下固定版本），不得事後才改成「訂金不退」。

Midao 的預設 UI 不應出現「訂金一律不退」的預勾選或隱藏規則。

## 8. UI 原則

方案進階設定應提供：

- `使用 Midao 建議取消規則`（預設三段式＋實際不可退成本基準＋訂金視為已付款）
- `自行設定`

預設範本應能讓導遊直接理解，例如：

```text
取消退款方式
● 使用 Midao 建議規則
  已付款（包含訂金）扣除已實際支付且無法退回的必要成本後，其餘退款
○ 自行設定

取消時間
出發前 8 天以上
出發前 4～7 天
出發前 0～3 天
```

避免要求導遊理解 refund policy enum、penalty rule 等技術名稱。

取消規則屬低頻商業設定，放在進階層，不塞進 Quick Edit（快速編輯）首頁。

## 9. 實作邊界

- #42：方案進階設定 UI、退款附件分享控制與 snapshot 一致性。
- #41：取消後對成團狀態、有效人數、退款待辦與不可退成本明細的生命週期影響。
- #12：實際退款金流／退款狀態，以及附件存取必須遵守 tenant／order 權限，不得自行公開附件 URL。
- #46：旅客下單前、訂單頁與退款結果誠實顯示適用政策、逐筆退款明細，以及只有被導遊主動分享的附件。

## 10. 尚未裁示

以下行為必須後續逐題裁示，不得自行推論：

1. 金流退款手續費由誰負擔。
2. 已成團後旅客取消造成低於成團門檻時，除既有 AT_RISK 流程外是否有額外補償規則。

在上述細節未裁示前，施工者可建立可配置資料模型與 UI 架構，但不得自行寫死固定退款比例、任意沒收訂金或任意新增扣款項目。
