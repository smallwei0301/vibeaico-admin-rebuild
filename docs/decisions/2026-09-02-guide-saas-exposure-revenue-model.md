# GUIDE SaaS＋Midao 前台曝光營收模型

> Owner Decision：2026-09-02
> 關聯：#48、#46、#45、#42、#1

## 1. 北極星

GUIDE 的主要營收方向採兩條彼此獨立的主線：

1. **SaaS（訂閱式後台）使用費**：導遊為後台接單、自動化、團隊協作與營運效率付費。
2. **Midao 前台曝光／推廣收入**：導遊可選擇購買額外曝光、主題活動或推廣版位。

平台目前 **不以每筆旅遊訂單抽成、退款仲裁費、代墊爭議款** 作為 GUIDE 核心營收模型。

正式月費、曝光方案價格與 Production 訂閱／推廣扣款仍需 Owner 另行拍板；本文件只固定產品與資料架構，避免後續收費模型走歪。

## 2. LISTED 與付費曝光必須分開

既有 `midao_listing = NONE | PENDING | LISTED | REJECTED` 只回答：

> **這個行程是否有資格出現在 Midao 前台？**

`LISTED` 不代表：

- 已購買曝光。
- 已付上架費。
- 排名一定更前。
- Midao 對該行程提供履約保證。

付費曝光必須使用另一個 promotion／campaign（推廣活動）概念，不得把付款狀態塞進 `midao_listing`。

這樣可以保留乾淨的資料語意：

```text
Listing eligibility（上架資格）
  NONE / PENDING / LISTED / REJECTED

Promotion（付費曝光）
  無推廣 / 排程中 / 進行中 / 已結束 / 已取消
```

## 3. 自然曝光與付費曝光

### 3.1 自然曝光

Midao 建議保留一層 organic listing（自然曝光）：

- 符合上架資格且 `LISTED + PUBLISHED` 的行程，可進自然搜尋／地區／分類結果。
- 自然排序使用可解釋的旅遊相關因素，例如內容完整度、地區／分類相關性、可售團次、可用日期、旅客評價與資料新鮮度。
- 不因「沒有買推廣」就把合法 LISTED 行程完全藏起來。
- 自然曝光是否包含在免費／個人／團隊 SaaS、或另收基本上架服務費，正式價格階段再拍板；資料模型不要先綁死。

### 3.2 付費曝光

第一版付費曝光建議採簡單、可理解的產品，不先做競價廣告平台：

- 精選行程／精選導遊。
- 地區頁置頂或推薦區，例如「阿里山精選」。
- 分類頁推薦，例如親子、文化、登山。
- 季節／節慶專題活動。
- Midao 首頁或內容文章的推廣卡位。

付費版位必須清楚標示 `推廣`、`贊助` 或等價文案，不得偽裝成純自然排名。

## 4. 第一階段收費實驗：固定期間／固定版位優先

MVP 不先做 CPC（每次點擊計價）、CPM（每千次曝光計價）、即時競價或複雜廣告帳務。

建議第一階段驗證：

```text
推廣標的：Trip / Guide / Theme
期間：開始日 → 結束日
版位：Destination / Category / Home / Campaign
預算或方案：固定期間固定費用（正式金額待定）
狀態：DRAFT / SCHEDULED / ACTIVE / ENDED / CANCELLED
```

理由：

- 導遊容易理解「買一週精選」而不是學廣告投放平台。
- Midao 可先驗證導遊願不願意為曝光付費。
- 帳務與退款較單純。
- 有足夠流量、點擊與訂單樣本後，再評估 CPC／CPM 或自助預算模式。

## 5. SaaS 與曝光費完全獨立

導遊可以：

- 只買 SaaS，不買 Midao 額外曝光。
- 使用自然 LISTED 曝光，不代表已購買推廣。
- 購買推廣，不改變 Trip／Plan／TourOrder 的資料 owner。
- 停止推廣，不影響後台資料、已成立訂單或自然上架資格。

未來若 SaaS 某方案「包含每月 X 次推廣額度」，也應在 billing entitlement（方案權益）層表達，不修改 `midao_listing` 的語意。

## 6. 不預設每筆交易抽成

目前 GUIDE 模式不新增：

- 每筆 TourOrder 固定百分比平台佣金。
- 因 Midao 導流成功就自動抽旅費。
- 旅客取消時 Midao 另收退款仲裁費。
- chargeback（信用卡爭議款）平台保證費。

如果未來要新增 booking commission（訂單抽成）、代收代付、履約保證或 marketplace 模式，必須另做 Owner Decision，並重新評估稅務、帳務、退款與平台責任。

## 7. 曝光成效資料

付費曝光至少需要誠實記錄：

- impression：推廣卡片實際被展示。
- click：點進行程／導遊頁。
- booking_start：開始預約／選方案。
- valid_order：形成有效 TourOrder。
- paid_order：實際有 qualifying payment 的訂單（若政策需付款）。
- attributed_revenue：可歸因訂單的實收金額，只作分析，不冒充平台收入。

報表要同時顯示分母，避免只寫「帶來 5 張訂單」卻不說曝光量。

第一版推廣費若採固定期間／固定版位，**帳單不依 click/order 數自動增減**；以上事件只用來算 ROI（投資報酬），降低帳務與歸因爭議。

## 8. 歸因原則

第一版避免複雜多觸點廣告歸因：

- 推廣連結／卡片帶 `promotion_id` 或等價 attribution token（歸因識別）。
- 旅客從推廣進入後，可把來源帶到 booking_start／TourOrder source metadata。
- 不把跨裝置、很久以前的曝光強行算成推廣成交。
- 正式 attribution window（歸因時間窗）待有流量資料後決定；在沒有可靠證據前，報表應顯示「可歸因訂單」而不是「這筆訂單一定是廣告造成」。

## 9. 前台排序與旅客信任

為避免「有錢的人永遠霸榜」傷害 Midao 品牌：

- 自然結果與付費推廣區塊在 UI／資料上分離。
- 付費內容清楚標示。
- 不允許已 `REJECTED`、未 PUBLISHED、無可售內容或安全審核未過的行程用付費方式繞過 listing gate。
- Promotion 結束後自然排名回到正常規則，不留下永久加權。
- Midao 可以拒絕不符合內容、安全或品牌規則的推廣，即使已是 SaaS 付費戶。

## 11. 收費產品拆分

正式對外至少分清楚：

| 收費項目 | 買到什麼 | 是否影響旅遊訂單抽成 |
|---|---|---|
| GUIDE SaaS | 後台、自動化、行事曆、團隊與營運能力 | 不影響；目前不預設抽成 |
| Midao 自然上架／審核 | 取得 Midao 前台自然曝光資格；是否另收基本費待 Owner 定價 | 不影響 |
| Midao 付費曝光 | 額外推薦版位／主題推廣／期間曝光 | 不影響 |
| 平台代建／營運協助 | Midao 協助整理行程、設定後台或營運服務 | 不影響 |

不得用一個模糊「平台費」把四種服務混在一起。

## 12. 目前仍需 Owner 最後拍板的只有價格與正式發布

架構層已可自主施工；以下數字仍保留 Owner gate：

- 免費／個人／團隊 SaaS 正式月費／年費與用量上限。
- 自然上架是否另收基本費，或包含在特定 SaaS 方案。
- 第一批固定期間曝光方案的正式價格。
- 是否提供 SaaS 綁曝光額度的 bundle（組合包）。
- Production 訂閱扣款與曝光購買正式上線授權。

在上述價格未拍板前，可以完成資料模型、事件、UI 原型、測試與匿名化成效報表，但不得啟動 Production 真實收費。
