# Owner Decision — GUIDE 響應式後台採五張手機 UI 基準稿

日期：2026-08-31

## 決策

Owner 選定 2026-08-31 對話中的五張手機 UI 圖，作為 GUIDE（導遊）模式新後台的正式視覺與資訊架構基準。

五個第一層入口固定為：

1. **首頁**
2. **團次**
3. **旅客**
4. **訊息**
5. **更多**

手機使用底部固定導覽；平板與桌機可以改成側欄或更寬版面，但仍必須維持同一套五個父層級，不能回到「二十幾個功能全部平鋪」的舊資訊架構。

## 視覺基準

- 手機優先，文字與可點擊區域偏大，不能把桌機密度硬縮進手機。
- 大標題、大卡片、大留白，資訊量低；一張卡只回答一個問題或提供一個主要動作。
- 主色為深森林綠，搭配鼠尾草綠、暖白／米白背景；橘色只用於待處理，紅色只用於危險／刪除。
- 首頁第一屏先回答「現在要處理什麼」，不要先塞滿營運圖表。
- 每個主要清單預設只露出少量最重要項目，再以「查看全部」進下一層。
- GUIDE 行事曆不採商店模式那種精細到每小時的日曆。手機以月／週摘要、日期是否有團、團數與當日團次列表為主；精確出發時間放在團次卡與團次詳情。

## 五張圖的角色

參考圖存放於 `docs/assets/guide-mobile-ui/`：

- `01-home.webp`：首頁／今天重點／接下來出發／週概覽／快速操作。
- `02-departures.webp`：團次／非小時制月曆／即將出發、募集中、已完成。
- `03-travelers.webp`：旅客／搜尋／狀態篩選／旅客摘要。
- `04-messages.webp`：訊息／待回覆優先／旅客訊息／系統通知。
- `05-more.webp`：更多／個人與連線狀態／設定功能分組。

圖片中的人名、數字、圖片、示範狀態只是 UI 示意，不是產品資料或業務規則。真實狀態與文字語意仍以 10、17、18、19 分冊及 Owner Decision 為準。

## 響應式尺寸底線

響應式（同一頁面依手機、平板、桌機自動調整）實作至少遵守：

- 主要頁標題：28–32 px。
- 區塊標題：20–24 px。
- 卡片主文字：17–20 px。
- 一般正文：至少 16 px。
- 次要文字：原則至少 14 px。
- 可點擊目標：至少 44 × 44 px。
- 手機左右內距：16–20 px。
- 卡片圓角：約 16–20 px。
- 區塊間距：16–24 px。
- 底部導覽：內容高度約 64–72 px，另加手機安全區。

以上是可用性底線，不要求每張圖逐像素複製。若字體放大或作業系統設定需要更多空間，元件應自然增高，不得裁字、重疊或水平溢出。

## 與既有規格的關係

- 本決策只決定 GUIDE 的呈現、資訊分層與響應式方向。
- Trip／Plan／Departure／TourOrder 資料模型不因 UI 重構而另造第二套。
- 付款、成團、通知、導遊可接案、PRIMARY／ASSISTANT 等規則仍以既有 canonical（正式唯一規格）為準。
- 舊 route（網址路徑）第一階段可保留，先重組導航與頁面殼層，避免大爆炸式改 API。
- Runtime（實際執行的網站程式）修改必須走 branch → PR（合併申請）→ CI（自動檢查）→ review（審查）→ merge（合併）。
- 本決策不授權 Production（正式環境）資料庫修改或部署。
