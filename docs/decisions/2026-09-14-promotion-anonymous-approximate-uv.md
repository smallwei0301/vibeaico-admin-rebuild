# 2026-09-14 Owner Decision — 推廣統計採匿名近似 UV

## Owner 決策

Owner 選擇 **B：保留 UV（Unique Visitors，不重複訪客數）的分析價值，但採匿名近似計算，不保存原始 IP。**

產品目的不是追蹤某個旅客，而是讓導遊知道「這段期間大約有多少不同訪客看過公開頁」，並可與 PV（Page Views，頁面瀏覽次數）一起判斷曝光成效。

## 隱私與資料邊界

- 不保存原始 IP 到資料庫、log、analytics event 或後台可查欄位。
- 後台導遊與租戶人員不得看見 IP。
- `visitor_hash` 使用「每日輪替 salt + 當次請求 IP + User-Agent／等價裝置資訊」計算後再落庫；原始輸入只在計算當下短暫存在，不作持久化。
- salt 每日輪替，避免形成可跨日長期追蹤同一訪客的穩定識別碼。
- 不建立訪客個人檔案、跨行程瀏覽歷史或長期行為画像。
- 不得把此匿名 hash 與 customer、traveler、LINE user、email、phone 或其他已識別身分資料做 join／關聯，以免把匿名統計重新個人化。

## UV 的產品語意

此 UV 是**近似值，不是精準人口計數**。

- 同一訪客在同一天、相近裝置／網路條件下多次瀏覽，應盡量只計為一個 UV。
- 因 salt 每日輪替，同一個人跨日回訪可能被重複計數。
- 共用網路、NAT、VPN、瀏覽器資訊變動等，也可能造成低估或高估。
- UI 必須使用「近似訪客」「近似 UV」或等價清楚文案，不得只寫「訪客人數」讓人誤以為是精準真人數。
- 說明文字至少要表達：此數值為匿名估算，可能因跨日回訪或裝置／網路變動而有誤差。

## 報表用途

允許用於：

- 7／30／90 天 PV／近似 UV 趨勢；
- QR／LINE／DIRECT／REFERRAL 等來源比較；
- Midao 曝光／推廣成效的整體趨勢；
- 「瀏覽很多但近似訪客很少」或「觸及面擴大」等產品分析。

不得用於：

- 找出特定旅客是誰；
- 長期跨日追蹤同一匿名訪客；
- 對單一匿名訪客建立再行銷、信用、風險或價格差別待遇；
- 對外聲稱精準到人的獨立訪客數。

## 工程預設（不是新的 Owner 產品取捨）

依 Issue #23 既有安全預設與 `2026-09-14-owner-decision-escalation-threshold.md`：

- 事件保留期限先採 **180 天**；日後可依實際資料量／法遵需求調整。
- 第一版採**即時計算／query-time aggregation**，不先新增預聚合日表；資料量真的成長到查詢成本成為問題時，再用實測證據升級。
- 零資料時回傳真實 0 與 `hasData:false`，UI 顯示「尚無資料」，不得畫示意假曲線。

這三項屬可逆、已有安全預設的工程決定，不再逐項升級 Owner。

## 實作要求

- `page_view_events` 不得有原始 IP 欄位。
- server-side tracking helper 應只輸出必要的匿名統計欄位。
- 測試需證明：原始 IP 不落 DB；相同日／相同輸入的 hash 行為可重現；跨日 salt 變更後 hash 改變；tenant 隔離成立。
- 公開頁埋點失敗不得影響旅客正常瀏覽頁面；統計屬次要副作用，錯誤需可觀測但不能把公開頁打掛。

## 非本決策內容

- 不在此決定廣告定價、曝光收費或轉換歸因計費。
- 不授權 Production DDL／DML、正式部署或正式資料寫入。
- 不允許保存原始 IP 以換取更精準的跨日 UV；若未來真的需要改變此隱私邊界，必須重新升級 Owner。
