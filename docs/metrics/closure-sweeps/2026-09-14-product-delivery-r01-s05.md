## 唯一提出的候選被推翻

scout 提出 **#246**（「匯出 Excel」三處假成功），理由是 10 個驗收框全勾、
證據 PR #248 已合併進 main（`2cc90bf`）。

覆核後不成立：

- #246 的 `state_reason` 是 **`reopened`**。
- 標題本身就寫著「格式已修（已完成），**報表頁內容仍是顧客名單冒充營運報表**（#250 承接）」。

也就是說，驗收框描述的那批工作確實完成了，但 Owner 重新開啟這張 Issue，
是因為另一個未被原驗收框涵蓋的問題仍然存在，且已轉交 #250。

**方法教訓**：「驗收框全勾 + 關聯 PR 已合併」是必要條件，不是充分條件。
一張被 reopen 的 Issue，它的驗收框反映的是**上一輪**的範圍。判定可關必須讀
`state`、`state_reason` 與標題／內文的現況描述，不能只比對勾選狀態。
這是本 Run 第二次 scout 方法錯誤（第一次見 Run ledger 的 `luna-ci-r01-s08`：
把 CI 失敗歸因於時間相鄰的 commit）。
