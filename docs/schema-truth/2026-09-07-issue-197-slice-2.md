## `bookings_view`

Production `bookings_view` was read back separately. It currently exposes the
booking base columns including `coupon_discount` and `points_redeemed`, then:

```text
customer_name
customer_phone
service_name
staff_name
customer_points
```

The live view remains an invoker-security view. Slice 0082 therefore performs a
`drop view` + `create view ... with (security_invoker = true)` after adding the
booking columns. This preserves the existing live output contract and avoids the
known PostgreSQL problem where `CREATE OR REPLACE VIEW` cannot safely absorb new
columns inserted into an expanded `b.*` position.

## What this slice deliberately does not adopt

The historical local migration overlay is **not** treated as a template for
Production. In particular:

- historical `0019_bug_report_attachments.sql` is not retired here because it
  also defines the private Storage bucket and restrictive Storage policy;
- historical `0020_booking_addons.sql` is not retired because it creates the
  `booking_addons` table itself;
- TEST-only fields such as `staff.availability_policy` remain outside this slice;
- no raw business rows are copied or changed.
